# M0.5 — HTTP Range Playback Findings (Experiment B)

Source: recorded server-side request log from the fixture server during
the automated experiment run (`results-media.json`,
`server-request-log` entry), plus the spike frontend measurements.

## What WebView2/Chromium actually requests

Observed request sequence for a 23 MB MP4 (moov at end — ffmpeg default,
NOT faststart):

```text
1. GET /media/mp4_h264_aac.mp4   Range: bytes=0-          → 206 (streamed ~5.8 MB, client aborts)
2. GET /media/mp4_h264_aac.mp4   Range: bytes=22970368-   → 206   ← moov fetch from EOF (84 623 bytes)
3. GET /media/mp4_h264_aac.mp4   Range: bytes=3145728-    → 206   ← playback-position prefetch
```

Conclusions for the M4 gateway:

1. **A single media element issues multiple CONCURRENT range
   connections.** The moov fetch (2) overlaps the head stream (1). A
   gateway that serializes requests per session will deadlock metadata
   parsing. (This exact bug was hit and fixed in the spike gateway —
   see M0.5-report.md §Security/Findings.)
2. The browser **aborts connections** once it has buffered enough
   (`client_disconnected` events). The server must tolerate mid-response
   disconnects as normal operation.
3. `Accept-Ranges: bytes`, `Content-Length`, `Content-Range`,
   `Content-Type` are all required and were exercised: 200/206/416 paths
   are covered by the gateway integration tests
   (`src-tauri/tests/spike_gateway.rs`).
4. Open-ended ranges (`bytes=N-`) are the dominant form; suffix ranges
   were not observed from Chromium media loads in this run but are
   implemented and tested server-side.

## Server-side streaming shape

The spike fixture server streams in bounded 64 KiB chunks and logs every
request; the spike gateway streams 256 KiB chunks with an artificial
per-chunk delay knob (0/50/200/1000 ms) for slow-network experiments.
Chunked streaming over loopback showed no stalls with the delay off; the
delay knob exists for M4-era stall experiments (used once during the
autorun; no stalls observed at 1.3 MB/s against a locally-complete
resource).

## Faststart note

ffmpeg puts moov at the END by default. The browser handles this fine
via the EOF range request (adds one round trip on loopback ≈ ms). For
real-world torrents, non-faststart files cost one extra round trip per
load — acceptable; `faststart` remuxing is NOT planned (M4 keeps
byte-for-byte torrent compatibility).
