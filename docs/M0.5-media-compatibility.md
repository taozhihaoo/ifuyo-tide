# M0.5 — WebView2 Media Compatibility Matrix

**Test machine:** Windows 11 x64 (build 10.0.26200), WebView2 Runtime
(Chromium/Edge 154.0.0.0 per user agent), no third-party codec packs
installed, ffmpeg 9.0.2 used only to GENERATE the media (not for
playback). All media is self-made (`testsrc2` + sine, 640×360, 90 s) —
see `scripts/generate-test-media.sh`.

**Method:** automated in-app matrix (`--spike-autorun`): each file is
loaded into a real `<video>` via the local fixture HTTP server
(range requests), then play → first frame → mid-file seek are measured.
All numbers are from the recorded run in
`%LOCALAPPDATA%\ifuyo\Tide\spike\results-media.json`.

| Container | Video | Audio | WebView2 load | Play | T_first_frame | Seek (50 %) | Verdict |
|---|---|---|---|---|---|---|---|
| MP4 | H.264 | AAC | 15 ms | PASS | 67–81 ms | 29–33 ms | **SUPPORTED** |
| WebM | VP9 | Opus | 7 ms | PASS | 20–33 ms | 24–26 ms | **SUPPORTED** |
| WebM | AV1 | Opus | 8 ms | PASS | 29–38 ms | 22–28 ms | **SUPPORTED** |
| MKV | H.264 | AAC | 8 ms | PASS | 22–25 ms | 30–38 ms | **SUPPORTED** |
| MP4 | HEVC (hvc1) | AAC | 13 ms | PASS | 78–160 ms | 30–33 ms | **CONDITIONALLY_SUPPORTED** |

Multiple runs were performed while iterating on the experiment harness;
ranges above span all recorded runs. Repeated runs showed stable results
(±40 ms).

## Field notes

- **Windows version:** 10.0.26200 (Windows 11 24H2+). HEVC playback
  succeeded on THIS machine; Windows HEVC support is conditional on
  OS/codec availability (HEVC Video Extensions / hardware decoder), so
  HEVC must never be assumed — M5 should probe
  (`MediaCapabilityDiscovery`) at runtime and report gracefully.
- **MKV plays directly** in WebView2 via `<video>` — the design
  assumption "MKV needs a native player" is FALSE on this stack for
  H.264/AAC content.
- **Seek is fast** (20–50 ms) for local/range HTTP sources at this scale.
- **Autoplay:** Edge's autoplay policy gates `play()` even for muted
  elements (play() stays PENDING, no rejection). Tide configures
  `--autoplay-policy=no-user-gesture-required` via
  `additionalBrowserArgs` (tauri.conf.json). **M5 must keep this** or
  gate playback behind an explicit user gesture.

## Status legend

- SUPPORTED — tested working on the reference machine.
- CONDITIONALLY_SUPPORTED — works here; depends on machine codecs
  (HEVC). Runtime capability probing required.
- NOT_TESTED — multi-audio-track MKV, ASS subtitles, AC-3: not part of
  the M0.5 matrix (M5 scope, per the milestone plan).
